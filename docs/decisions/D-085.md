# D-085 Common motherboard Super I/O chips and explicit write policy

Accepted · 2026-11-11 · Updates D-003
Decision: extend motherboard monitoring beyond NCT6687D to Nuvoton EC (NCT6683D, NCT6686D), Nuvoton bank chips (NCT6779D–NCT6799D), ITE IT86xx/IT87xx (including dual-chip setups at `0x2E`/`0x4E`), and Fintek F718xx via the PawnIO `LpcIO` module (`src/sensors/board.*`, `board_chips.*`). Replace the strict read-only policy with the [hardware write inventory](../hardware.md#writes-pitot-performs).
Reason: supporting Nuvoton bank chips, ITE, and Fintek requires configuration-mode entry/exit, bank/index writes, and clearing the Nuvoton I/O space lock (`0x28` [4], which many ASUS boards enable at boot — the same unlock performed by LHM, FanControl, and Linux `nct6775`).
Implementation points:
- Each slot (`0x2E`, `0x4E`) uses its own `LpcIO` handle because `ioctl_select_slot` clears registered port ranges.
- Snapshot slots carry `BoardChannel` (`chip`, `input`), and `main.cpp` rebuilds the sensor mask when `board_layout` changes.
- Fan control, voltage, and clock writes remain strictly out of scope.
Status: NCT6687D verified on hardware; NCT67xx, ITE, and Fintek decoding is unit-tested (`tests/board_chips_test.cpp`) and awaits verification on those boards.

See [motherboard sensors](../subsystems/board-sensors.md) for detection and decoding.
