# D-033 GPU data sources and ADLX proprietary license isolation

Modified by D-081: NVIDIA cards get the same extended metrics through `PitotNvidia.dll`. Release packaging: D-091.

Accepted · 2026-11-04 · User decision
Decision:
- **Two binaries, two license domains**: `Pitot.exe` (MIT + embedded LGPL-2.1 PawnIO modules) contains and links no AMD ADLX code. `PitotAdlx.dll` (`src/adlx/`) is the only component that includes ADLX headers and is loaded on demand via the pure-C interface in `src/sensors/adlx_abi.h`. This prevents AMD's anti-reverse-engineering clause from conflicting with the LGPL PawnIO modules.
- **No ADLX headers in the repo**: `.gitignore` excludes `third_party/adlx/`. `scripts/get-adlx.ps1 -AcceptAmdLicense` downloads ADLX SDK v1.5 and verifies its SHA-256. Without it CMake skips `PitotAdlx.dll` and `Pitot.exe` falls back to D3DKMT.
- **Always-on vs on-demand metrics**: D3DKMT supplies 3D utilization, core clock, core temperature, and VRAM every 2 s for any GPU. Hotspot temperature, VRAM temperature, board power, and fan speed are read via ADLX only while the flyout is open, then `ADLXTerminate` + `FreeLibrary` runs on close (keeping ADLX loaded adds ~7 MB and 9 threads; unloading drops it to ~2.7 MB and does not leak across reloads).
- **Release**: distributing `PitotAdlx.dll` requires bundling an end-user agreement matching ADLX Appendix B stating it applies only to that DLL. Since 2026-11-16 this is `PitotAdlx-EULA.txt`, which always travels next to the DLL. The DLL is built on the maintainer's machine (user decision) and packed into the release installer and zip with `scripts/repack-adlx.ps1` (D-091); CI never downloads the SDK, because AMD's license allows use of the SDK only at the licensee's own sites, so the installer and zip that CI builds do not contain the DLL.
Rejected:
- ADL SDK (MIT): rejected by the user in favor of ADLX in a separate DLL.
- Compiling ADLX into `Pitot.exe` or committing ADLX headers: violates AMD's license and conflicts with LGPL.
