# D-006 One process, three threads, lock-free triple-buffer snapshots

Accepted · 2026-11-04
Decision: the UI thread only draws; the sampling thread writes into a lock-free single-writer single-reader triple buffer (`src/sampler/triple_buffer.h`) and notifies the UI with `PostMessage`; the ETW consumer thread runs only while the storage or network panel is open.
Reason: the UI always reads a complete snapshot without locks or waiting. Unlike a double buffer, a triple buffer gives writer and reader private slots plus a hand-over slot so a late UI frame never has its snapshot overwritten mid-read.
