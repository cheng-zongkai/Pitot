# D-081 NVIDIA extended GPU metrics through the driver's NVML and public NVAPI

Accepted · 2026-11-10 · Extends D-033
Decision: on NVIDIA GPUs (PCI vendor `0x10DE`), read hotspot temperature, memory temperature, board power, and fan speed via an optional `PitotNvidia.dll` (`src/nvidia/`) loaded only while the flyout is open. `Pitot.exe` never links NVML or NVAPI, and no NVIDIA headers are added to the repository.
Implementation points:
- `PitotNvidia.dll` loads `nvml.dll` strictly via `LOAD_LIBRARY_SEARCH_SYSTEM32` or `%ProgramW6432%\NVIDIA Corporation\NVSMI\nvml.dll` (never the default search path).
- Hotspot prefers `nvmlDeviceGetTemperatureV` (`NVML_TEMPERATURE_GPU_MAX`) with fallback to `nvmlDeviceGetTemperature`; memory temp uses `NVML_FI_DEV_MEMORY_TEMP` (82); power uses `nvmlDeviceGetPowerUsage`; fan uses `nvmlDeviceGetFanSpeedRPM` (fan 0). Unsupported GeForce calls hide individual metrics rather than failing open or reporting 0.
- If NVML omits memory temperature or fan RPM, fall back only to public `nvapi64.dll` calls (`NvAPI_GPU_GetThermalSettings` v2 memory target, `NvAPI_GPU_GetTachReading`) loaded from `System32`. Never use `nvmlDeviceSet*` or unpublished NVAPI IDs.
- Third-party disclaimer/MIT notices for NVML and NVAPI declarations live in `THIRD_PARTY_NOTICES.md` and `src/nvidia/pitot_nvidia.cpp`.
Status: reviewed against public NVML/NVAPI headers; not yet verified on NVIDIA hardware.
Rejected: unpublished NVAPI entry points, vendoring full NVAPI/NVML headers, or linking `nvml.dll` into `Pitot.exe` alongside LGPL PawnIO modules.
