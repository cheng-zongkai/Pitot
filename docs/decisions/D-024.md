# D-024 Flyout implementation: software D2D, factory release, timer animation

Modified by D-049: `WS_POPUP | WS_CAPTION` with a collapsed non-client area is required for DWM Acrylic.

Accepted · 2026-11-04 · Updated 2026-11-13
Decision:
- **Window**: owned by the hidden main window (`WS_EX_TOOLWINDOW | WS_EX_TOPMOST`), DWM rounded corners (`DWMWCP_ROUND`), Acrylic (`DWMSBT_TRANSIENTWINDOW`), `DwmExtendFrameIntoClientArea(-1)`. See the [flyout layout](../subsystems/flyout.md#window-and-lifecycle) for current geometry.
- **Rendering**: D2D software `ID2D1DCRenderTarget` onto a 32-bit premultiplied DIB, then `BitBlt` to the window so DWM Acrylic shows through transparent regions.
- **Resource release on close**: release the DIB, render target, isolated DirectWrite factory (`DWRITE_FACTORY_TYPE_ISOLATED`), and D2D factory on hide, then call `HeapSetInformation(HeapOptimizeResources)`.
- **Disable IME in main process**: call `ImmDisableIME(-1)` so focusing the flyout does not load TSF/IME DLLs into resident memory. Settings text input runs in a separate process (D-042).
- **Theme**: `theme = system` follows Windows system mode (matching the taskbar), not app mode.
- **Animation**: 200 ms ease-out cubic slide + fade driven by a 16 ms `WM_TIMER` with `timeBeginPeriod(1)` held only during the 0.2 s animation (and restored on stop/hide/destroy), plus phase-timing logs. `DwmFlush()` on the UI thread is forbidden because it blocks the shared explorer input queue (D-013).
Rejected:
- Hardware `ID2D1HwndRenderTarget`: loads the GPU user-mode driver (+30 MB private commit that stays resident, plus ~8 MB growth per rebuild).
- Keeping the D2D factory across closes: holds ~33 MB for the geometry cache and WARP device.
- Calling `DwmFlush()` on the UI thread or adding a fourth thread for vsync pacing.
